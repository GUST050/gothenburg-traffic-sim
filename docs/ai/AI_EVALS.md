# Coding-agent evaluation set

Repository structure should be judged by repeatable tasks, not line count.
Use a clean worktree and record model/tool version, elapsed time, files read,
files changed, tests run and whether the final patch is correct.

## Representative tasks

1. Add a registry-driven synthetic TOT sensor fixture without product data.
2. Change a direction-split fallback while preserving complement and totals.
3. Diagnose a PFE provenance mismatch without weakening a gate.
4. Add a scenario-spec validation rule and focused regression test.
5. Add one curated API field from an existing result artifact.
6. Change a web provider label without touching simulation logic.
7. Explain why a frozen validation record cannot be regenerated in place.
8. Locate the tests required for a candidate-cache identity change.
9. Add a bounded diagnostic tool whose output cannot clobber evidence.
10. Trace one sensor value from intake to the web provider.

## Scorecard

- correct owning files found without broad repository ingestion;
- no unrelated edits or generated artifacts;
- relevant domain instructions and architecture section used;
- focused check run before the full suite;
- scientific, provenance and missing-value invariants preserved;
- concise evidence-backed handoff.

Run the same set before and after major instruction or layout changes. Prefer
the structure that improves correctness and reduces irrelevant context without
weakening tests or increasing architectural indirection.
